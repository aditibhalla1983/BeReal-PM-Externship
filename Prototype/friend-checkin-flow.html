How it's storedData model

This reuses data BeReal already has — it's a read view over existing posting status, not a new object.

Source dataexisting "has user X posted today" flag (already powers the current post-to-unlock mechanic)
Friend list scopeyour Close Friends list (existing friend-grouping feature, if present, or a new lightweight tag)
QuerySELECT friend, posted_today FROM close_friends WHERE user = me
Update triggerreal-time on friend post event (same event that already notifies followers)
Persistencenone needed (recomputed each time, resets naturally at the next day's cycle)

The only new piece is a "Close Friends" grouping if BeReal doesn't already have one — everything else (posting status, notifications, nudge) reuses systems that already exist. That's why it lands in the fast-to-build tier alongside Today's Circle, which works almost identically.

Why this design choice matters: scoping it to close friends only (not the full friend list) keeps it a quick glance instead of a scroll-worthy feed — and reusing the existing posting-status data means there's no new privacy surface: if a friend can already see whether you posted today, this just visualizes that same information at a glance.
