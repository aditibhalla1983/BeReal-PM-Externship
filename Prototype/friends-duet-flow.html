How it's storedData model

This is the most build-intensive idea on the list — it needs a real-time match check, not a background/periodic computation.

Triggeron every post event (check runs the moment you post, not on a schedule)
Match windowWHERE friend.posted_at BETWEEN (my_post_time \u00b1 N min)
Match scopefriends only (not friends-of-friends or public)
Pairing recordnew lightweight object (links two post IDs + timestamp gap — similar to the Friend Throwback pairing, but created live instead of computed periodically)
Race condition handlingneeds care (if both friends post within seconds of each other, both clients need to resolve to the same pairing)

The real-time nature is what pushes this to "Low" on Fast to Build in the prioritization table — a live cross-user match at post time is meaningfully harder than anything else on this list, which all read existing data rather than computing something new the instant it happens.

Design note: because the reward isn't guaranteed, it works best framed as a bonus/surprise, not a core mechanic to design around — pairing it with something reliable like Golden Memory (which always delivers something) keeps every post feeling worthwhile even on days with no Duet match.
