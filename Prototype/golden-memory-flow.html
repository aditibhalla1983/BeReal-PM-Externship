How it's stored — and how "golden" is decidedData model

The interesting part of this feature isn't storage — it's the selection logic for what counts as "golden." A memory earns a golden score from signals that already exist:

Reaction/comment counthigher = more likely to be picked (existing engagement data on the original post)
Manually tagged tripsboosted weight (if the user has tagged a post as part of a vacation/album)
Time-tier bucketlast month / last year / older (so it doesn't always pick the same recency window)
Already-unlocked logunlocked_memories(user_id, post_id, date) (new, small table — prevents repeats)
Selectionweighted random from top-scoring pool (not always the single highest score, to keep it a surprise)

Two new pieces here: a lightweight golden score (computed from data that already exists — reactions, tags, recency) and a small unlocked-memory log to avoid repeats. Everything else — the photo, the original post — is unchanged. More setup than Daily Question, but still no new content type or major backend system.

Why this design choice matters: tying the reward to posting (not just opening the app) reinforces the exact behavior BeReal wants — and because it's guaranteed regardless of friend activity, it fixes the one real weakness in the existing "post to unlock friends" mechanic: some days, there's simply nothing to unlock. This always has something.
